# 运行流畅度与操作体验优化

用户已授权继续优化运行、操作便利性和界面，并要求整理文件；无法清理时提供可手动删除的明确路径。沿用此前确认的文件夹导入、同步双窗格、同一目标跟踪及人工修正流程。保持现有源码目录，不打包、不提交、不上传，不改原始采集数据。

## 调查与取舍

真实 114507 数据九次切帧的界面呈现中位耗时约 91.2 ms；每帧重复扫描点云边界两次，颜色插值也占据显著耗时。播放在读取呈现之后再额外等待整个帧间隔，实际节奏会叠加读取耗时。跟踪面板的表单和按钮次序混杂，逐帧检查依赖主窗口，缺少快速聚焦目标。

考虑过整体换界面框架、增加并行预读、局部性能和流程改进三条路径。此次选择局部改进：框架重写没有必要，并行预读会增加源读取竞争和内存；现有结构中已有可测的冗余。这个技术选择由实现者作出，属于已授权优化范围，不要求用户重新审批。

## 行为

- 同一次视口刷新共享准确点云边界，刷新、换数据、编辑后重新计算，避免陈旧范围；保持显示、处理和导出数据不变。
- 简化颜色插值的临时数组，保持全部色表、端点、NaN、形状和 float32 输出语义。只以同输入测量比较报告收益。
- 播放的目标间隔包含读取和呈现耗时；慢帧不跳过、无并行读取，暂停和取消仍有效。已加载帧上开始播放不会重读当前帧；末尾开始播放从首帧继续。
- 点云/图像预览中提供 Space 播放/暂停、Home/End 首末帧；输入框仍按正常键盘行为工作。底部显示明确首末帧按钮，状态提示保持稳定。
- 跟踪面板按「目标 → 当前帧修正 → 相邻帧关联」分区，添加上一帧/下一帧、当前原始帧号和聚焦目标。人工框保护、保存格式、取消和源身份检查不变；小屏幕内容可滚动。
- 深浅主题一致，主要操作突出，说明简洁；不把开发信息放进日常操作流程。
