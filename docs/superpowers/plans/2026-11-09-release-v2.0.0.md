## Evidence ledger

- The environment was missing PyInstaller, its hooks, and optional LAS/E57 dependencies. Installed the pinned `requirements-build.txt` using uv; all 98 installed packages pass dependency compatibility checks. Existing runtime versions were unchanged.
- Before the fix, PyInstaller's module graph found `rosbags.typesys.stores` but neither `ros1_noetic` nor `ros2_humble`. Added a shared hook collecting the dynamically selected type stores; both platform specs register the hooks directory.
- Prepared isolated synthetic ROS1 BAG, ROS2 SQLite BAG, ROS1 MCAP and ROS2 MCAP fixtures with three frames of 1,000 points, 320 × 180 rgb8 images and status messages. Source reads assert actual decoded kinds and content, not merely successful file opening. Prepared separate workspaces for actual EXE acceptance.
- Independent static review found no Critical or Important blockers. Its current-documentation minor is part of the final release documentation update; final executable/archive behavior remains a separate verification gate.
- Fresh complete Windows suite after version/build dependency preparation: 507 passed, 16 skipped, 140 subtests passed, 5 pre-existing deprecation warnings; 536.34 seconds, exit 0.
- First native EXE acceptance exposed an actual frozen-only failure: MCAP compressed images and CameraInfo fell back to raw messages with `No module named 'rosbags.serde.primitives'`. ROS serializers generate their primitive imports as source strings, invisible to static module analysis. The archive regression check failed on the same missing module. Added a dedicated `rosbags.serde` collection hook; the corrected build must pass both archive inspection and real reader/UI checks before delivery.
- Reproduced a separate display-recovery error with real Qt bitmaps: successfully forced redraws accumulated as failures and incorrectly paused playback. The watchdog now counts failed presentations only and resets after a newly presented bitmap. Two tests verify both successful-recovery behavior and persistent-failure reporting. The targeted 14-test set passed; independent read-only review found no blockers.
- Final complete Windows regression after the layout and recovery changes: 509 passed, 16 skipped, 140 subtests passed, 5 existing deprecation warnings; 594.56 seconds, exit 0. `git diff --check` passed. This does not claim a fix to all underlying scheduling delays; final EXE behavior is checked separately.
- Actual EXE acceptance verified frames 400–536 advancing in both panes, pause/jump, reload retaining frame/view/sync, tree association over frames 395–405, stepping to automatic suggestions, three-view manual correction, save and reopen. Both themes and approximately 1280×850 / 1024×700 windows were inspected; small annotation panels intentionally scroll.
- Acceptance found one remaining status bug: cancelling the overview left the footer saying it was reading. The existing cancel-options test reproduced the defect before adding the missing cancelled status; the three cancel/reconfigure checks then passed. Final delivery rebuild and regression include this fix.
- Final delivery build exited 0 in about 167 seconds. Archive resources, dynamic ROS stores/serializer, OpenCV files and version 2.0.0 passed; release size 229,775,360 bytes, SHA-256 `746e21dbd4b319825b7252f942ab4d368a8096c39c4a4c1272a53b9182dc73d5`. Isolated reads through this exact payload passed all four ROS1/ROS2 BAG/MCAP fixtures and all five real MCAP streams.
- Final full regression after the cancellation fix: 509 passed, 16 skipped, 140 subtests passed, 5 existing warnings, 621.45 seconds, exit 0. The exact delivery EXE displayed raw rgb8 / PointCloud2, reopened the real workspace and showed the corrected cancellation footer. It exited normally without a running-session marker.
- Compared all 9 original capture files against the initial size/mtime inventory: unchanged. Cleanup of the new build/diagnostic directories was rejected by automatic approval with only `blocked by policy`; no deletion retry or workaround. Remaining disposable paths and the rejection are documented in `docs/cleanup-guide.md`.
