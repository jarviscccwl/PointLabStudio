# 运行与操作体验优化验收

本轮完成于 2026-11-09，沿用现有源码目录和文件夹同步、同一目标跟踪流程。双击项目根目录 `start.bat` 运行。未打包 EXE、未创建提交、未上传 Git，原版 v1.3.0 EXE 保留。

## 使用变化

- 点云刷新共用同一次边界计算，简化颜色插值产生的临时数组。修改点云、替换数据或改变可见性后仍重新计算正确范围。
- 播放间隔计入读取与显示耗时，减少每帧多等一个完整间隔的停顿；读取较慢时仍按顺序播放。已加载帧开始播放不重复读当前帧，末帧再次播放从首帧继续。
- 底部增加首帧与末帧按钮。点云/图像预览获得焦点时，`Space` 播放/暂停，`Home` / `End` 暂停并跳到首帧/末帧。场景中的空格显隐操作和输入框编辑保持可用。
- 目标跟踪面板分为「选择目标」「当前帧修正」「关联相邻帧」，增加面板内上一帧/下一帧、原始帧号及「聚焦目标」。聚焦只调整相机，不替换点云或标注。
- 跟踪面板适配深浅主题，默认尺寸 460 × 740；小窗口可滚动，主要操作均可到达。人工锚点保护和标注保存格式沿用原有逻辑。

## 真实数据与显示耗时

数据目录：`D:\2026_10_14\selective_20261014_114507`，包含 950 帧 PCAP 点云及 1733 帧 MCAP 图像。使用 Windows 原生 Qt 窗口，同样的 1280 × 800 逻辑尺寸、数据、缓存和设置，将浏览位置 400、401、402 各访问三次。

对照组只在探针进程内临时恢复旧版的颜色插值和重复边界计算，其余代码保持相同；仓库文件没有为测量来回覆盖。两组等待均释放 Python GIL，避免测试等待本身阻塞后台读取。

| 指标 | 旧显示路径 | 本轮显示路径 |
| --- | ---: | ---: |
| 界面呈现处理耗时中位数 | 92.170 ms | 50.784 ms |
| 九次切帧中的点云边界扫描 | 18 次 | 9 次 |
| 帧就绪总耗时中位数 | 113.917 ms | 71.484 ms |

本次抽样中，界面呈现处理耗时约减少 45%。这是特定数据、机器和九次切帧的对比，不代表软件整体提速 45%，也不是 GPU 帧率、持续播放或长时间内存压力测试。

另将七种色表在 558,280 个输入值上与旧公式比较，最大绝对误差不超过 `1.1920929e-7`，输出仍为 float32；端点、NaN、空数组、非连续输入和形状有回归覆盖。

早期 `performance-before.json` / `performance-after.json` 使用 Qt 测试等待，对后台读取产生干扰，不用于最终耗时结论。最终结果以 `performance-baseline-controlled.json` 和 `performance-after-controlled.json` 为准。

## 回归与独立审查

针对性检查已覆盖边界重用和失效、颜色数值、读取耗时、播放暂停与变速、首末帧、快捷键冲突、跟踪导航、聚焦和暂时离线的数据源。

完整回归：**447 项通过、16 项跳过、140 项子测试通过**，耗时 435.45 秒，进程退出码 0。5 条警告来自既有 Dash 测试插件和 Qt 弃用接口，没有失败。使用以下命令在 Windows 原生 Qt 平台运行：

```powershell
$env:QT_QPA_PLATFORM='windows'
$env:PYTHONFAULTHANDLER='1'
.\.venv\Scripts\python.exe -B -m pytest -q -p no:cacheprovider --durations=5
```

完整测试期间仅补充文档和应用内快捷键帮助文字，帮助文本所在 Python 文件的语法检查通过；未再修改功能逻辑。

独立代码审查没有发现待处理的问题。额外探针验证：单帧读取 55 ms、请求 100 fps 时仍按 `[1, 2, 3, 4, 5, 6]` 顺序播放并在末尾停止；快速播放/暂停及跳转 `2 → 4 → 3` 仅呈现最终帧，计时器停止。

几何跟踪的原有限制仍适用：不识别物体类别，不利用 IMU 补偿自车运动，需要人工检查遮挡、相似目标和较大运动。详细范围见 [文件夹同步与目标跟踪验收](capture-tracking-2026-11-08.md)。
