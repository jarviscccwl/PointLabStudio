# 3D 框内点云提取与性能优化

日期：2026-11-09。本页记录框内提取与性能优化的实现和源码验证。随后按用户要求打包为本地 v2.0.0，并将源码交付到改名后的 `preview` 分支；EXE 未上传。最新成品、校验值及发布验收见 [v2.0.0 preview 交付记录](release-v2.0.0-preview-2026-11-09.md)。

## 使用方式

打开采集文件夹，在「3D 框选」中建立或选择目标，使用三视图调整范围。

| 需求 | 操作 | 结果 |
| --- | --- | --- |
| 提取当前帧 | 点击三视图底部「提取框内点」 | 独立点云加入场景，可继续处理、导出、撤销和重做 |
| 提取关联多帧 | 点击按钮右侧箭头 →「批量提取有框帧到文件夹…」 | 每个有框帧一个 PCD，并附 `index.json` 来源清单 |

当前帧提取按完整点云及三轴旋转框计算，不受预览抽样影响，保留源坐标、字段及当前显示设置。启用图像赋色时会保留当前显示的 RGB；结果数组与源点云独立，原始采集包保持原样。来源信息包括文件、话题、原始帧号、两类时间戳及框参数，可随 `.pls` 保存。

批量操作处理当前目标全部已有框的帧，包括导入范围外仍保留的标注；使用每帧原始点云字段，不逐帧合成图像赋色。文件名包含原始帧号及时间戳，清单还记录人工/自动框和点数。清单 `frame_index` 从 0 开始，`frame_number` 与界面一致从 1 开始。空框保留清单记录，`point_count=0`、`file=null`，不生成空 PCD。

批量逐帧读取以限制内存占用，可取消。全部成功后才将临时目录发布为 `target-目标名-随机编号`；取消、源变化或读取失败不留下不完整批次。结果已经发布后才到达的取消不撤回已完成文件，并仍提示保存位置。批量文件独立保存在磁盘，不随场景撤销删除。

## 为什么没有整套改为 C

实测主要瓶颈包括三视图逐点创建 Python 界面对象、点云范围计算、重复建立 MCAP reader，以及启动时提前加载关联算法。已改为 Qt 原生批量转换、NumPy 批量计算、复用读取器及按需加载。

Qt 本身采用 C++，NumPy 和渲染库也已有原生计算。整套更换语言并不能自动解决重复计算和加载时机问题，且会扩大功能回归范围。本轮保留现有框架，改造实测热点，没有新增自建 C/C++ 扩展或安装编译器。

| 测量项 | 优化前 | 优化后 | 说明 |

| 3D 框调整中位耗时 | 76.68 ms | 25.45 ms | 减少约 67% |

| PCAP 单帧读取中位耗时 | 90.94 ms | 85.73 ms | 交错各 14 次 |

启动对照只测源码模块加载，不包含 EXE 解包和完整窗口启动；不能将首次冷启动与后续热启动直接比较。旋转绘制改为屏幕实际物理分辨率，保留抗锯齿，减少低/中 DPI 下默认超采样的额外像素计算。PCAP 新旧解码坐标最大差为 0.0 m，强度一致。
